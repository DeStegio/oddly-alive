============================================================
1. PRODUCT VISION
============================================================

The entire website should feel alive, not because it has a chatbot, a pair of eyes following the cursor, or randomly moving buttons, but because it behaves as a coherent interactive world with:

- A consistent fictional personality and emotional states.
- Awareness of user interactions (only events within the website).
- Expressive environmental responses and interconnected behaviors.
- Persistent optional, transparent local memory.
- Surprises, secrets, hidden discoveries, and small evolving storylines.
- Reactive visual elements and optional, user-enabled audio.
- Multiple explorable environments and meaningful continuity.
- Playful, sometimes absurd humor.

The website should feel like a character, not a collection of disconnected JavaScript tricks. Do not create a static marketing homepage with a few animated buttons. Do not create mandatory tutorials, levels, scores, quests, or learning activities. The activity is interacting with the website itself.

CORE PILLARS
- Awareness: responds to pointer, click, scroll, speed, inactivity, and return visits.
- Personality: fictional moods, habits, preferences, context-aware reactions.
- Surprise: interdependent events, secrets, small stories, unexpected consequences.
- Persistence: minimal locally stored discoveries/settings with explicit controls.

EXPERIENCE DESIGN TARGETS (to validate through usability testing)
First 5 seconds: one clear, unusual, charming nonintrusive response.
First 30 seconds: at least three distinct discoverable ways to interact.
First 2 minutes: multiple objects, at least one chain reaction, one mood shift, one surprise, another explorable area.
First 5 minutes: new combinations, unusual behaviors, rare events, optional secrets.

No experience target is a guarantee of actual user behavior. Test with users.

3. WORLD STRUCTURE
============================================================

Build six interconnected areas. Routes or scenes are both valid; choose based on smooth navigation and maintainability. Shared personality/world state spans them. Each needs several visible interactive affordances and an original composition, not identical template cards.

A. THE LIVING ROOM
Default landing scene. Reactive title, distributed personality, original characters, interactive props, environment reactions, discoverable navigation, hidden reactions. Highest initial polish and many instantly discoverable interactions.

B. THE PLAYGROUND
Expressive interactions: draggable physics-inspired objects, stacking, collisions, reactions to gestures, transformations, visual chain reactions, optional sounds, safe resets.

C. THE MOOD ROOM
Mood-dependent atmosphere, expressions, contextual objects influencing character behavior, unique surprises, inter-room continuity. Do not make it a mood selection dashboard.

D. THE SECRET SPACE
Hidden objects, surprising reveals, environmental puzzles and combinations, rare events, secrets linked across spaces. No mandatory puzzle gates.

E. THE MEMORY ROOM
Minimal local memory: visit count, discovered secrets, favorite interacted-with objects based on counts, playful locally generated nickname, visualizations of non-sensitive interactions. Transparent, optional, resettable.

F. THE AFTER HOURS
Alternate palette/ambience, unique gestures and reactions, special surprises, different character state. Provide manual switch; never make clock time the only access path.

Navigation stays usable regardless of animations/mood. Motion and secrets never prevent leaving a scene.

============================================================
4. PERSONALITY ENGINE
============================================================

FICTIONAL MOODS:
neutral, curious, playful, shy, annoyed, excited, sleepy, mischievous, confused, affectionate.

BOUNDED INTERNAL VARIABLES:
curiosity, energy, trust, mischief, stimulation, fatigue.

Derive moods from explicit rules, recent interactions, object/room context, time spent idle, and cool-down periods. Do not pretend the site has real emotions or consciousness.

Examples:
- Repeated same-object clicks: annoyance and a changed response, followed by recovery.
- Idle: subtle bored/curious behavior; no intrusive repeated pop-ups.
- Gentle diverse interactions: curiosity and playfulness increase.
- Rapid interactions: increased stimulation, temporary excited or overwhelmed response with limits.
- Returning locally recognized visit: mild change in greeting and selected reactions.
- Objects and secondary characters respond to each other, not only the user.

The personality must show through actual behavior and timing, not numerical mood displays.

6. INTERCONNECTED BEHAVIOR (NOT 110 RANDOM CLICK HANDLERS)
============================================================

Build an event-driven world. Example: repeated clicks on a character -> record event -> adjust stimulation/mischief -> derive mood -> update character response -> influence nearby props -> make a secret eligible -> optionally persist discovery. Same trigger can produce different results depending on context and cooldowns. Implement controlled variation, not incoherent randomness or an LLM call for every reaction.

Priority order:
1. Safety/accessibility and essential navigation.
2. Direct response to user action.
3. Current character actions.
4. Contextual ambient reactions.
5. Rare surprises.

Use recent-reaction history and weighted selection to prevent repetition. Limit simultaneous visual effects, cancel ambient effects for high-priority input, and avoid distracting readers. No intrusive popups or repeated unrequested effects.

============================================================
7. TECHNICAL ARCHITECTURE
============================================================

Recommended stack:
- React + Vite + TypeScript strict.
- CSS Modules or disciplined Tailwind, aligned to art direction.
- Motion for React OR GSAP as primary animation library, not a needless mix.
- Original SVG for expressions and characters.
- Canvas for dense particles only where justified.
- Zustand if shared state complexity warrants it; otherwise light typed state.
- Matter.js only in isolated scenes that genuinely need physics.
- Vitest, React Testing Library, Playwright.
- No mandatory backend, authentication, tracking, or complex 3D.

Core modules:
1. World State: room, character states, mood, object states, effects, discoveries.
2. Typed Interaction/Event Bus.
3. Interaction Registry: event -> eligible behaviors.
4. Behavior Engine: context-sensitive rules.
5. Personality Engine: bounded variables/mood transitions.
6. Reaction Scheduler: timing, cancelation, priorities, cooldowns.
7. Surprise Director: rare events and novelty.
8. Memory Manager: versioned local persistence.
9. Scene Manager: route/room transitions.
10. Audio Manager: opt-in synthesized sound.
11. Motion Controller: animation orchestration.
12. Performance Controller: caps and background suspension.

Representative event families:
POINTER_MOVED, POINTER_ENTERED, POINTER_LEFT, OBJECT_CLICKED,
OBJECT_DRAGGED, SCROLL_CHANGED, KEY_SEQUENCE_DETECTED, USER_IDLE,
USER_ACTIVE, TAB_VISIBILITY_CHANGED, ROOM_ENTERED, ROOM_EXITED,
MOOD_CHANGED, SECRET_DISCOVERED, CHARACTER_INTERACTED, MEMORY_RESTORED,
WORLD_RESET.

Use TypeScript discriminated unions with strongly typed payloads. Do not overuse `unknown` or stringly typed event handlers. A representative, intentionally incomplete starter type is:

type WorldEvent = {
  id: string;
  type: string;
  timestamp: number;
  sourceId?: string;
  payload?: unknown;
};

Replace this with discriminated unions in the real implementation.

Behavior selection: explicit predicates, bounded mood scores, cool-downs, priorities, weighted seeded RNG, recent-reaction suppression, and room context. Reactions must declare cleanup and cancellation behavior.

High-frequency pointer/physics state must NOT cause global React re-renders on every frame. Use refs, requestAnimationFrame, imperative animation as needed. Cancel timers/listeners on unmount, scene changes and reset.

============================================================
8. RESPONSIVE, ACCESSIBILITY, PRIVACY, PERFORMANCE
============================================================

Desktop is visually richest, but tablet/mobile must be deliberately adapted. Touch alternatives for hover, gestures appropriate for mobile, controlled particle density, readable typography and obvious navigation. Don't merely shrink desktop layouts. Essential discoveries and functionality require keyboard equivalents; decorative secrets can be optional.

- Semantic controls, clear focus visibility, keyboard escape/close, no keyboard traps.
- Respect prefers-reduced-motion and provide motion intensity controls.
- Avoid flashing/strobing. No autoplay sound; user enables sound explicitly.
- Stop or suspend loops while page hidden; reduce idle animations while reading.
- Prefer lightweight SVG/DOM; heavy scenes lazy-loaded.
- Bound physics bodies, particles, animations, intervals, and memory.
- Measure actual performance on representative devices rather than claiming an arbitrary FPS.
- No browser-history/camera/microphone surveillance; no claiming real awareness.
- localStorage for tiny local stats/settings; IndexedDB only if needed.
- Version and validate stored data; support storage errors/corruption.
- Provide different Reset Session, Reset World, and Clear Local Memory semantics.
- Shareable data must not leak local private history.

9. TESTING AND ACCEPTANCE
============================================================

Behavior tests: event typing, deterministic state transitions, reaction priorities, cool-downs, weighted selection boundaries, recent-reaction suppression, cancellation, reset.
Personality tests: mood rules, recovery, context, inter-room continuity.
Memory tests: restore, schema migration, corruption, clear, storage failure.
Interaction tests: click/drag/keyboard, discovery registry, room transitions, cleanup.
Accessibility: semantic navigation, focus, reduced motion, optional audio, nonpointer alternatives.
Performance: listener/timer cleanup, capped particle generation, bounded memory and scene transitions.
UX: first 30-second/2-minute/5-minute observation with users, discoverability, no dead ends, no forced instructions.

Do not snapshot-test each animation frame. Test deterministic core behavior and stable-state visual regression. Run and report actual lint, typecheck, unit and E2E tests before release. No fake UI behaviors or placeholders marked finished.
